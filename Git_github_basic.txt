Clone and Status
=================================
Clone: Cloning a reprository from remote to local machine
Status: To display the status of the code
To see a hidden file using vs code use "ls -Force" which is a power shell command, ls -a willl not work which is a linux command.
1. git clone <Some link>
2. git status
# If you are making any change in the cloned repo/file, your file or repo will come in modified stage
    and if you want to commit the file fist you need to add it
So Bacially we have two steps process after modified
    a. "git add <file>..." to update what will be committed
    b. commit to make it final.
Whenever, we are using git status, we can have four types of status.
1. Untracked : New files that git does not yet track
2. Modified : Changes files
3. Staged : File ready to commit.
4. Unmodified : No change

=================================
Add and commit
=================================
add - Add new or changed file in you working directory to the git staging area.
    git add <file_name>  -- to add the individual file
    git add .   -- to add all the changed file.
commit - It is the record of change.
    git commit -m "Some message"

================================
Push and Pull command
================================
Push : Upload local repo content to remote repo.
    git push origin main

It means:

Push my local changes from the main branch to the remote repository named origin.

1. git push

git push sends your committed changes from your local repository to a remote repository, such as GitHub.

Example flow:

Your Local Machine  ──────►  GitHub
      git push
2. origin

When you clone a repository:

    git clone <repository-url>

Git automatically gives the original remote repository the name origin.

You can check it using:

    git remote -v

Example:

origin  https://github.com/username/Basic.git (fetch)
origin  https://github.com/username/Basic.git (push)

So origin basically refers to your GitHub repository URL.

3. main

main is the branch name you want to push.

You can check your current branch using:

git branch

Example:

* main

The * means you are currently working on the main branch.

Putting it all together

Suppose your situation is:

Local Repository
└── main
    └── README.md (with your changes)

        │
        │ git push origin main
        ▼

GitHub Repository
└── main
    └── README.md (updated)

So:

git push origin main

means:

Take the commits from my local main branch and push them to the remote repository called origin.

Usually, before pushing, you follow this sequence:

git status
git add .
git commit -m "Added new changes"
git push origin main

The flow is:

Working Directory
       │
       │ git add .
       ▼
Staging Area
       │
       │ git commit -m "message"
       ▼
Local Repository
       │
       │ git push origin main
       ▼
GitHub Remote Repository

One important point: git push only pushes committed changes.
 If you modify a file but haven't run git add and git commit, those changes won't be pushed.

 Init command
 ============================
 git init
 git remote add origin <url>

 git branch  (to check branch)
 git branch -M main (To rename branch)
 git push origin main
 git push -u origin main (if you want to set upstream)

git init is used to initialize a new Git repository.

git init
What does it do?

Suppose you have a normal folder:

MyProject/
│
├── app.py
└── README.md

When you run:

git init

Git creates a hidden .git folder:

MyProject/
│
├── .git/
├── app.py
└── README.md

The .git folder stores Git's information, such as:

Commit history
Branch information
Configuration
Staging information

Now your folder becomes a Git repository.

Example

In VS Code PowerShell:

cd C:\Users\shivn\Documents\MyProject
git init

You may see:

Initialized empty Git repository in C:/Users/shivn/Documents/MyProject/.git/

Then you can follow this flow:

git init
git add .
git commit -m "Initial commit"

If you want to connect this local repository to GitHub:
Create a new repo in github.

git remote add origin <repository-url>
git branch -M main
git push -u origin main
git init vs git clone
Command	Purpose
git init	Create a new Git repository in an existing local folder
git clone <url>	Download/copy an existing repository from GitHub

For example:

Starting from scratch:

Create Folder → git init → git add → git commit → git push

Using an existing GitHub repository:

git clone → git add → git commit → git push
